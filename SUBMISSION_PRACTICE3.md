# Практика 3 — список с деталями

Приложение использует моковые данные по персонажам Rick and Morty, как требует первая практика.
Сетевые запросы к API будут добавлены отдельно в ветке `practice4`.

Реализовано:

- Single Activity и экраны на Jetpack Compose;
- MVVM: каталог и поиск находятся в `CharactersViewModel`, выбранный персонаж — в `CharacterDetailsViewModel`;
- нижняя навигация между персонажами, локациями и эпизодами;
- оптимизированный список `LazyColumn`;
- переход по карточке на экран подробной информации и возврат назад;
- моковые данные, соответствующие полям Rick and Morty API.

Каждый экран создаёт свою ViewModel в области своей записи навигации. Экран деталей
получает ID через `SavedStateHandle` и самостоятельно находит персонажа в моковых данных.
При отсутствующем или неизвестном ID показывается «Персонаж не найден» с кнопкой возврата.
Корневой компонент отвечает только за навигацию.

## Что показать в записи

1. Переключить все три вкладки нижней навигации.
2. Вернуться к персонажам и прокрутить список.
3. Ввести имя в поиск и очистить строку.
4. Открыть карточку персонажа, прокрутить детали и вернуться назад.

Проверка: `gradlew.bat testDebugUnitTest lintDebug assembleDebug` — успешно.
Четыре unit-теста проверяют поиск и получение деталей по корректному, неизвестному и отсутствующему ID.
На Pixel 8 / Android 17 проверены открытие разных персонажей, сохранение поискового запроса
после возврата из деталей и поворот обоих экранов.
